# Randoro
A boxing interval timer that fires random audio cues so you have to react to the unpredictable.

## How it works

**Home screen** — a heartbeat trace, the one from the app icon, sweeps across the screen to a heartbeat sound and reveals the letters of "randoro" as it passes. It lands, expands into an 'o', and the tagline fades in. Tap **Get Ready** to continue.

**Setup** — configure your session before starting:

- **Round Structure** — set warm-up, number of rounds, work duration, rest duration, and cool-down. Tap any duration to open a scroll wheel. The swap button (↔) flips whether work or rest comes first.
- **Workout Style** — three tabs:
  - *Preset* (default) — *Intensity* sets how often cues fire (Low fires infrequently, High fires constantly). *Attack Length* is the execution time, the fixed time you get to attack after each cue, based on the number of punches you throw (1-2 gives a short window, 5-6+ a longer one).
  - *Manual* — *Intensity* is set by *Time* (*Avg. Anticipation Time*, the variable wait before each cue) or by *Count* (*Attacks per Round*). *Attack Length* is the fixed *Execution Time* after each cue in seconds, set to fit the number of punches you throw. *Avg. Time Between Beeps* shows the variable anticipation time plus the fixed execution time. If the attacks don't fit the round, you're told and the workout won't start until you change something.
  - *Simple* — no random cues, a plain interval timer.
- **Feedback** — toggle screen flash and vibration on each cue. Greyed out in Simple, since there are no cues.

Tap **ENTER** to continue.

**Running** — the screen shows the current phase (warm-up, work, rest, cool-down), a large countdown, and elapsed/remaining time. In a work round it also shows how many of the round's beeps have played, e.g. "2 of 3 beeps". Audio cues fire at random intervals within the bounds you set. On each cue:
- A beep plays
- The screen flashes (if enabled)
- The phone vibrates (if enabled)

Before each work round, a long low beep gives a 10-second warning, then three long beeps count 3-2-1 into the round-start beep.

Use the arrow buttons (‹ ›) to jump between phases. Tap **PAUSE** to pause mid-round and **RESUME** to continue. Tap ✕ to end early.

Audio continues in the background and on the lock screen, so it's safe to pocket the phone mid-session.

## Stack

React Native + Expo (SDK 54). iOS is live on the App Store. Android is in beta testing on Google Play.

iOS and Android native code is generated by Expo, so `ios/` and `android/` are not in
the repo.

## Setup

Run once after cloning, for either platform.

```bash
npm install
node scripts/generate-sounds.js
```

The second command generates the WAV files the app plays. The build fails without them.

## iOS

Prerequisites: Node 18+, current Xcode, Apple Developer account configured in Xcode,
physical iPhone (some audio behaviour does not surface in the simulator).

### Run on a device

```bash
npx expo run:ios --device
```

### Release

1. Xcode → Product → Archive
2. Distribute → App Store Connect
3. Window → Organizer to view archives

The build number increments per archive. The app is live, so raise `version` in `app.json` above the released version before archiving an update.

## Android

Prerequisites: Node 18+, JDK 17, Android SDK with NDK `27.1.12297006`, and a physical
device with USB debugging enabled or an Android Studio emulator.

Set these in `~/.zshrc` or `~/.zprofile`:

```bash
export JAVA_HOME="/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
```

### Run on a device

```bash
adb devices
npx expo run:android --device
```

### Release

Create an upload keystore. Store the password in a password manager and back up the
`.jks` file. Losing it means the app can never be updated under the same package name.

```bash
keytool -genkeypair -v -storetype PKCS12 \
  -keystore ~/randoro-upload-key.jks \
  -alias randoro-upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

Add the credentials to `~/.gradle/gradle.properties`. Use an absolute path for the store
file. Do not quote the values.

```properties
RANDORO_UPLOAD_STORE_FILE=/Users/<you>/randoro-upload-key.jks
RANDORO_UPLOAD_KEY_ALIAS=randoro-upload
RANDORO_UPLOAD_STORE_PASSWORD=<password>
RANDORO_UPLOAD_KEY_PASSWORD=<password>
```

`plugins/withSigningConfig.js` adds a `release` signing config that reads these
properties to `android/app/build.gradle` whenever Expo generates `android/`. Nothing
needs editing by hand.

Increment `android.versionCode` in `app.json` before each upload, then generate the
native project and build:

```bash
npx expo prebuild --platform android
cd android
./gradlew signingReport     # release must show the upload keystore, not debug
./gradlew bundleRelease
```

Upload `android/app/build/outputs/bundle/release/app-release.aab` to Play Console.

### Expo Go vs the dev build

Randoro's background audio depends on native config from `app.json` (the iOS
`UIBackgroundModes: audio` entry and the Android permissions). **Expo Go ignores
this config**, so beeps stop in the background and on the lock screen there.

Always run the app through the **dev build** produced by `npx expo run:ios` or
`npx expo run:android`, not Expo Go. Once the dev build is installed,
`npx expo start` can serve JS reloads to it for pure-JS changes (layout, styling,
animations). But you must open the **dev build** app on the device, not Expo Go.
They look identical; only the dev build has the native config. Delete Expo Go
from the device to avoid connecting to it by accident.

## Sound assets

Beep files (`ping`, `double`, `double_rest`, `warmup`, `cooldown`, `warning`, `countdown`) generated at 44.1 kHz, 16-bit, mono PCM. Each is a harmonic-rich tone (odd harmonics over the fundamental) for perceived loudness, normalised to its true measured peak. Every beep file is padded to 1 s, because Android's ExoPlayer plays nothing on the first play of a shorter clip.

The silence track is 5 minutes of low-amplitude 110 Hz sine at 8 kHz mono (~4.8 MB). Two players take turns playing it at low volume while the running screen is open, so audio never stops. Continuous audio keeps background beeps firing, holds the Bluetooth route open, and keeps an idle Bluetooth output from clipping the first beep. See `memory/project_audio_session.md`.

Regenerate when the script changes:

```bash
node scripts/generate-sounds.js
```
