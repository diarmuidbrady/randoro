Current as of 21 Oct 2026. Audio decisions are in [[project_audio_session]].

## Stack

- Expo SDK 54, React Native 0.81.5 (new architecture), expo-audio 1.1.1, react-navigation (stack), react-native-svg.
- expo-av is removed. It's deprecated from SDK 55, and its config plugin added a microphone permission. Use expo-audio.
- expo-asset is pinned to `~12.0.13`. expo-audio declares `expo-asset: "*"` as a peer dependency, so npm installed the SDK 55 version at the top level.
- No picker library. `src/components/WheelPicker.js` is a JS scroll wheel (ScrollView with `snapToInterval`, 44 px rows, 5 visible). It handles both `onMomentumScrollEnd` and `onScrollEndDrag`, because Android skips the momentum event after a slow drag. To screen readers it's an "adjustable" control.
  - Why the picker went: `@react-native-picker/picker` only drew dropdowns on Android, and 2.11.1 (the version SDK 54 pins) crashed on a Galaxy A14. Its C++ was compiled without RN 0.81's `RN_SERIALIZABLE_STATE`, so heap corruption showed up in `RNCAndroidDialogPickerProps`.

## Native project and builds

- `/ios` and `/android` are generated and gitignored. **Changes to app.json (versionCode, permissions, plugins) only reach them through `npx expo prebuild`.** `expo run:*` skips prebuild when the folder already exists.
- `plugins/withSigningConfig.js` sets up Android release signing, so a fresh checkout needs no hand edits.
- Permissions: app.json `blockedPermissions` removes `RECORD_AUDIO`, `SYSTEM_ALERT_WINDOW` and both storage permissions. The expo-audio plugin has `microphonePermission: false` and `recordAudioAndroid: false`. Both are needed, because expo-audio's library manifest also declares `RECORD_AUDIO`.
- Android release: `npx expo prebuild --platform android`, then `./gradlew bundleRelease` in `android/`. Bump `versionCode` in app.json for each upload.
- iOS release: archive in Xcode → Distribute → App Store Connect. The build number increments with each archive. The app is live, so each App Store update also needs a higher `version` in app.json than the released one.
- Background audio and the native config only work in the dev build (`npx expo run:ios` / `run:android`), not Expo Go.

## Sounds

- `assets/sounds/` is generated by `scripts/generate-sounds.js` and gitignored. Run it before building.
- Beeps are a harmonic-rich tone (odd harmonics) for perceived loudness, normalised by their measured true peak.
- Every beep file is padded to 1 s. Mechanism, from the Media3 1.8.0 source: while paused, ExoPlayer still renders about once a second, so a clip shorter than the AudioTrack buffer (`clamp(4 × device minimum, 250 ms, 750 ms)`) is written in full. The sink then stops a track that never started, and the first `play()` reports playing → ended with no sound. Seeking resets this, so later plays work. Upstream: ExoPlayer issue #8569.
- `assets/heartbeat.wav` (tracked) is made by `scripts/make-heartbeat.sh` from a stock heartbeat mp3. It has 0.6 s of leading silence, so Bluetooth wakes before the thump and the file is over 1 s. The beat is EQ'd towards 220 Hz and limited, because phone speakers can't play its sub-80 Hz energy.

## Workout generation

- Durations are `{ minutes, seconds }` objects, converted to seconds when the workout starts.
- Pings per round: `floor(workDuration / (avgFrequency + minGap))`. n pings make n + 1 gaps, each at least `minGap`, so no ping lands on a round edge.
- `randomBeeps: false` (the Random Beeps switch) generates no pings, making a plain interval timer.

## Countdown

- A `warning` beep plays 10 s before each work round, then a `countdown` beep at 3, 2 and 1 s. They play during the phase before the round.
- Beeps that don't fit in that phase are skipped:
  - 5 s warm-up (the default): the warning would fall before the workout starts, so you hear only 3-2-1.
  - 10 s rest: the warning would play over the rest-start beeps, so it's skipped.
- No countdown between back-to-back work rounds.

Rejected:
- 5-4-3-2-1: too many beeps on every rest.
- A rising count in equal 25 Hz steps (400→500 Hz): sounded out of tune.
- Softer sounds (decaying envelopes, fewer harmonics, a wood-block clack): 7–15 dB quieter than the ping over the first 200 ms, too quiet over music.

## Home animation

- Native-driven: a single `progress` value (0 → 1) runs over 1750 ms. The ECG path is a set of interpolation lookup tables built from `computeY`. An earlier version drove it from JS with a state update every frame, which dropped frames on Android.
- The trail is 30 dots spaced 2 frames apart. Each dot adds about 15 native animated nodes, all set up before the first frame moves. On the A14 debug build the pause before movement was 60 dots → 1.18 s, 30 → 0.50 s, 12 → 0.41 s. A smoother trail should come from an SVG line, not more dots.
- On Android the native animation clock starts at its first UI frame, which can be well after mount. Anything that must line up with the dot has to follow the dot's own value, not JS timers started at mount:
  - Letters fade in from the trail's tail position.
  - The heartbeat is scheduled from the dot's first movement, aiming its thump at the R peak (`AUDIO_LATENCY_MS` is a tuning guess).
- The dot is red only on the R spike. White and red are stacked opacity layers, because the native driver can't animate colour.

## Ghost beep

An intermittent flash with no sound was an un-awaited `seekTo(0)` before `play()`. `playSound` now always awaits the rewind. See [[project_ghost_beep_fix]].
